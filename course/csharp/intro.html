Introduction to C#

C# (C-Sharp) is a modern, object-oriented programming language developed by Microsoft as part of the .NET framework. C# has roots from the C family (C, C++) and the language is similar to Java. Among various languages supported by .NET framework, C# is the most popular and widely used language.

Since, Microsoft started cross-platform support initiative through new version of .NET framework called .NET Core (now .NET) C# now can be run on many different devices, from Internet of Things (IoT) devices to the cloud and everywhere in between. You can write apps for phone (android, iOS), desktop and laptop computers and servers.

C# is a compiled language; however, unlike C or C++, which get compiled directly to machine code (native code) that runs directly on the hardware, C# gets compiled to an intermediate language (IL) known as Common Intermediate Language (CIL). This intermediate code is not specific to any particular platform or architecture.

  1. Compilation to CIL:

    2. When you write a C# program, the C# compiler (csc.exe) first compiles your source code into CIL. This intermediate language is platform-independent, meaning it can run on any platform that has a compatible runtime (like the .NET runtime).

  2. The Role of .NET Runtime (CLR):

    3. The compiled CIL code is packaged into assemblies (usually in .exe or .dll files). These assemblies are executed by the Common Language Runtime (CLR), which is the runtime environment provided by the .NET framework. The CLR is responsible for:

    • Just-In-Time (JIT) Compilation

      • The CLR takes the CIL code and compiles it into native machine code specific to the platform it’s running on at runtime (this process is called JIT compilation).

    • Garbage Collection

      • The CLR also manages memory through garbage collection, which automatically reclaims memory that is no longer being used.

  3. Platform Independence:

    4. This process allows C# programs to be platform-agnostic in a sense, meaning they can run on any platform that has a .NET runtime implementation, such as Windows, Linux, or macOS (via .NET Core or .NET 5+). In contrast, C or C++ programs must be recompiled for each specific platform to produce native machine code.

This two-step process (C# → CIL → JIT compilation) provides both portability and the advantages of managed code (e.g., memory management and exception handling), unlike C or C++ where the developer has to manage memory manually.
